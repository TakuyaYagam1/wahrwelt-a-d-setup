# Проверка исходников

Быстрая встроенная проверка запускается так:

```sh
./control scan PATH --patches
./control scan PATH --json
```

Встроенный сканер запускается системным Python, не требует внешних библиотек и работает без сети. Для него используется `rules/defense.json`. Карточки находок и исправления находятся в [каталоге](vulnerabilities/README.md).

Форматы отчетов и контекста используют имя `wahrwelt`. Старые отчеты нужно пересоздать перед сравнением.

Он ищет знакомые AST и текстовые признаки. Regex могут совпасть с комментарием или примером, а опасный вызов сам по себе не доказывает уязвимость. Проверка не понимает межфайловые потоки данных и правила конкретного сервиса. Особенно трудно ей находить ошибки доступа к объектам, владения данными и бизнес-инвариантов. Нулевой отчет не подтверждает безопасность.

Дополнительные утилиты запускаются отдельно и не меняют формат встроенного отчета:

```sh
./control scan-external PATH --engine all --json
./control scan-external PATH --engine semgrep
./control scan-external PATH --engine trivy
```

В `PATH` нужны [Semgrep](https://semgrep.dev/docs/getting-started/quickstart) и
[Trivy](https://trivy.dev/docs/latest/getting-started/installation/).

По умолчанию запускаются оба движка. Код завершения `0` означает полный отчет без находок, `1` - полный отчет с находками, `2` - ошибка, пропущенная часть файлов или недоступный движок. При `2` результат нельзя считать чистым. Для каждой утилиты установлен предел времени 1-1800 секунд. Размер файла ограничен 16 MiB, дерево - 100000 файлов и 1 GiB. Символическая ссылка или превышение лимита останавливает проверку.

Semgrep Community Edition работает с локальными правилами в `rules/semgrep.yml`. Сейчас там две проверки потока: URL из Python HTTP-запроса до HTTP-клиента и данные JS/TS запроса в SQL-строке. Вторая проверяет сам текст SQL, поэтому значение в параметрах запроса не считается частью SQL. Это небольшие правила для ручной проверки, а не полный анализ приложения. `.semgrepignore` отмечается как неполный охват. Утилита не получает правила из реестра; метрики и проверка обновлений выключены.

Trivy проверяет зависимости на известные CVE, конфигурацию инфраструктуры и секреты. Это не поиск ошибок в произвольной логике приложения. Нужные базы должны уже находиться в локальном кэше. Если база устарела или отсутствует, отчет будет частичным. Запуск явно отключает локальные файлы настроек и исключений из рабочей директории; встроенные правила поиска секретов остаются включены. Найденное значение секрета не попадает в отчет.

Все проверки выполняются локально: исходники не загружаются, проект не собирается и не запускается. Trivy по умолчанию не обновляет базы. Флаг `--update-trivy-db` отдельно разрешает загрузить базы, но не отправляет исходники. На стенде при проверке стояли Trivy 0.72.0 и Semgrep 1.161.0; это версии данного компьютера на 2026-10-13, а не закрепленные требования.

Для углубленной проверки Python пригодится [Bandit](https://bandit.readthedocs.io/en/latest/), Go - [gosec](https://github.com/securego/gosec). Универсальной замены ручному разбору логики сервиса нет.

Свои правила Semgrep входят в MIT-лицензию проекта. Сами движки, сторонние правила и базы имеют отдельные лицензии.

## Проверка исправления

Для находки проследите путь данных от входа до опасного вызова и проверьте условия срабатывания. После исправления запустите тесты сервиса, включая пример, который воспроизводил ошибку. Сравнивайте отчеты одной версии сканера с одинаковыми параметрами:

```sh
./control scan PATH --json > before.json
# Исправьте код и выполните тесты сервиса.
./control scan PATH --json > after.json
python3 -I -S scripts/defense_diff.py before.json after.json --json
```

Исчезновение сигнала само по себе не доказывает исправление. Частичный отчет означает неполную проверку.

## Свои правила

Правила хранятся в `rules/defense.json`, тесты - в `tests`, независимые примеры - в `tests/fixtures`. Для нового правила добавляйте уязвимый и исправленный варианты, карточку в каталоге и проверку ограничений детектора. Команды проверки приведены в корневом [README](../README.md).
