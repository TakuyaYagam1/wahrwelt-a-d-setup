# Neo

Neo получает от Farm конфигурацию, адреса команд и настройки флагов, а затем отправляет Farm найденные флаги. Эксплойты добавляет и настраивает администратор через CLI Neo.

В корне проекта выполните `./control init` и настройте команды и формат флага в `.env`.
Скрипт можно проверить до запуска серверов:

```sh
./control neo test ./sploit_example.py 192.0.2.10 --timeout 10s
```

Проба выполняется в отдельном временном контейнере. Она показывает stdout, stderr,
код завершения и найденные флаги, не регистрирует задание и не отправляет флаги.
Формат флага берется из `FARM_FLAG_FORMAT`. При превышении времени код выхода равен 124.

Для работы по расписанию запустите Farm и Neo:

```sh
./control farm
./control neo
./control neo add ./sploit_example.py --id example --disabled
./control neo enable example
./control neo info
./control neo tail example --count 20
./control neo update example --interval 10s --timeout 5s
./control neo disable example
```

`add` без `--disabled` сразу включает задание. `update` меняет параметры запуска;
для загрузки новой версии файла повторите `add` с тем же `--id`.
`./control neo single example` запускает загруженное задание один раз по всем
настроенным командам и передает найденные флаги Farm.

Пути к файлам считаются от текущего каталога. Если скрипту нужны соседние файлы,
добавьте `--dir` к `add` или `test`: control скопирует каталог скрипта целиком.
Символические ссылки и специальные файлы не принимаются. Исходные файлы не меняются.

Корневой [sploit_example.py](../../sploit_example.py) уже принимает адрес цели, делает HTTP-запрос,
извлекает совпадения формата `FARM_FLAG_FORMAT` и печатает каждый флаг отдельной
строкой. Настройте в начале файла порт, путь и выражение, затем допишите запрос
или проверку сервиса в `run_exploit`:

```sh
./control neo test ./sploit_example.py 192.0.2.10 --timeout 10s
./control neo add ./sploit_example.py --id example --disabled
./control neo enable example
```

Neo получает только строки из stdout и передает совпавшие флаги в Farm. Диагностику
пишите в stderr. Формат в `FLAG_PATTERN` должен соответствовать `FARM_FLAG_FORMAT`
из `.env`.

Для соединения с Farm используется адрес `http://farm:5000`, маршруты `/api/get_config` и `/api/post_flags`, заголовки `Authorization` и `X-Token`.

`./control neo` запускает сервер, Redis и worker, который выполняет включенные задания.
Farm запускается отдельно. `./control neo down` останавливает только Neo с его Redis
и worker, сохраняя задания. Статус и журнал: `./control neo status` и `./control neo logs`.
Отправка из Farm в систему соревнования включается через `./control farm submit-up`.

`NEO_KEY` и `NEO_WORKER_KEY` должны быть разными ключами длиной не менее 32 байт. Обычный worker не получает админский ключ. Его ключ разрешает только RPC для опроса, загрузки заданий и файлов, потоков команд и отправки журналов. Сеть Redis закрыта для worker. Рассылка команд выключена.

Worker работает без root, привилегий и Docker socket. Задания получают отдельное окружение без ключей управления Neo; клиент также закрывает чтение своей памяти через `/proc` для процессов того же UID. При остановке завершается группа процессов задания. Все процессы заданий все еще работают под UID worker внутри одного контейнера, поэтому это не изоляция заданий. По протоколу worker получает от Neo настройки Farm, включая пароль для прямой отправки флагов. Не запускайте worker для непроверенных команд без отдельной изоляции.

Образы используют обновляемые теги Go, Python, Alpine и Redis. Базовый worker
устанавливает `requests` из короткого `client_env/requirements.txt` с нижней
границей версии. Если скриптам нужны дополнительные библиотеки, добавьте их туда.
