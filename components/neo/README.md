# Neo

Neo получает от Farm конфигурацию, адреса команд и настройки флагов, а затем отправляет Farm найденные флаги. Эксплойты добавляет и настраивает администратор через CLI Neo.

В корне проекта выполните `./control init` и настройте команды и формат флага в `.env`.
Скрипт можно проверить до запуска серверов:

```sh
./control neo test ./sploit_example.py 192.0.2.10 --timeout 10s
```

Проба выполняется в отдельном временном контейнере. Она показывает stdout, stderr,
код завершения и найденные флаги, не регистрирует задание и не отправляет флаги.
Формат флага берется из `FARM_FLAG_FORMAT`. При превышении времени код выхода равен 124.

Для работы по расписанию запустите весь стенд одной командой `./control all-up`
(Farm, Neo с Redis и worker, Packmate) или только Farm и Neo:

```sh
./control farm
./control neo
```

## Команды Neo

Все команды вызываются как `./control neo КОМАНДА`. `ID` это имя задания,
которое вы задали через `--id` при `add`.

| Команда | Что делает |
| ------- | ---------- |
| `test ФАЙЛ АДРЕС` | Один локальный запуск скрипта на одной цели в отдельном контейнере. Показывает stdout, stderr, код выхода и найденные флаги. Ничего не регистрирует и не отправляет. |
| `add ФАЙЛ` | Загружает скрипт в Neo как задание. Повторный `add` с тем же `--id` заменяет его новой версией. |
| `info` | Показывает состояние: задания, подключенные worker, настройки Farm. |
| `update ID` | Меняет параметры запуска задания без загрузки файла. |
| `enable ID` / `disable ID` | Включает или выключает задание. Выключенное задание хранится, но не запускается. |
| `single ID` | Запускает задание один раз сразу по всем целям из `targets.txt`. |
| `tail ID` | Показывает журнал задания. |
| `broadcast` | Выполняет команду на всех клиентах. В стенде выключена (`NEO_ALLOW_BROADCAST_COMMANDS=false`). |

### Флаги

`test`:

| Флаг | По умолчанию | Смысл |
| ---- | ------------ | ----- |
| `--timeout` | 30s | Предел времени запуска. При превышении код выхода 124. |
| `--dir` | выкл. | Передать весь каталог скрипта, если нужны соседние файлы. |

`add` и `update`:

| Флаг | По умолчанию | Смысл |
| ---- | ------------ | ----- |
| `--id ИМЯ` | путь к файлу | Имя задания. Только для `add`. Задавайте явно, чтобы управлять заданием по короткому имени. |
| `--interval` | 30s | Как часто запускать задание по каждой цели. |
| `--timeout` | 30s | Сколько ждать один запуск, затем процесс завершается. |
| `--endless` | выкл. | Бесконечный режим для скриптов, которые работают постоянно и печатают флаги по мере нахождения. Занимает слоты `NEO_WORKER_ENDLESS_JOBS`; при значении 0 такие задания не идут. |
| `--disabled` | выкл. | `add`: загрузить выключенным. `update`: выключить задание. |
| `--dir` | выкл. | Только для `add`: загрузить каталог скрипта целиком. |
| `--yes` | выкл. | Только для `add`: не спрашивать подтверждение при загрузке новой версии. |

`tail`:

| Флаг | По умолчанию | Смысл |
| ---- | ------------ | ----- |
| `--count`, `-n` | все строки | Сколько последних строк показать. |
| `--version` | текущая | Журнал конкретной версии задания. |

Примеры:

```sh
./control neo add ./sploit_example.py --id example --disabled
./control neo enable example
./control neo update example --interval 10s --timeout 5s
./control neo single example
./control neo tail example --count 20
./control neo info
./control neo disable example
```

`add` без `--disabled` сразу включает задание. Параллелизм worker задают
`NEO_WORKER_JOBS` и `NEO_WORKER_ENDLESS_JOBS` в `.env`.

Корневой [sploit_example.py](../../sploit_example.py) принимает адрес цели, делает HTTP-запрос
и печатает ответ в stdout. Флаги по `FARM_FLAG_FORMAT` ищет сам Neo, поэтому формат
в скрипте задавать не нужно. Настройте в начале файла порт и путь, затем допишите запрос
или проверку сервиса в `run_exploit`:

```sh
./control neo test ./sploit_example.py 192.0.2.10 --timeout 10s
./control neo add ./sploit_example.py --id example --disabled
./control neo enable example
```

Диагностику пишите в stderr.

Для соединения с Farm используется адрес `http://farm:5000`, маршруты `/api/get_config` и `/api/post_flags`, заголовки `Authorization` и `X-Token`.

`./control neo` запускает сервер, Redis и worker, который выполняет включенные задания.
Farm запускается отдельно. `./control neo down` останавливает только Neo с его Redis
и worker, сохраняя задания. Статус и журнал: `./control neo status` и `./control neo logs`.
Отправка из Farm в систему соревнования включается через `./control farm submit-up`.

`NEO_KEY` и `NEO_WORKER_KEY` должны быть разными ключами длиной не менее 32 байт. Обычный worker не получает админский ключ. Его ключ разрешает только RPC для опроса, загрузки заданий и файлов, потоков команд и отправки журналов. Сеть Redis закрыта для worker. Рассылка команд выключена.

Worker работает без root, привилегий и Docker socket. Задания получают отдельное окружение без ключей управления Neo; клиент также закрывает чтение своей памяти через `/proc` для процессов того же UID. При остановке завершается группа процессов задания. Все процессы заданий все еще работают под UID worker внутри одного контейнера, поэтому это не изоляция заданий. По протоколу worker получает от Neo настройки Farm, включая пароль для прямой отправки флагов. Не запускайте worker для непроверенных команд без отдельной изоляции.

Образы используют обновляемые теги Go, Python, Alpine и Redis. Базовый worker
устанавливает `requests` из короткого `client_env/requirements.txt` с нижней
границей версии. Если скриптам нужны дополнительные библиотеки, добавьте их туда.
